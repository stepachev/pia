# pia: для продвинутых

Всё техническое из прежнего README: провайдеры и роли моделей, конфиги, устройство служб, сборка окна, правила для агентов. Простое описание — в [README](../README.md). Пути вроде `mac-app/build.sh` и `install.sh` — от корня репозитория.

Личный ИИ-помощник для Mac. Работает с любым провайдером (Claude, ChatGPT, Gemini, OpenRouter, локальные модели и др.). Состоит из фоновой службы (Node.js + Pi Durable), команды `pia` в терминале и окна `pia.app` (автозапуск): двойной правый Shift открывает окно с захватом контекста, двойной правый Option — показывает/прячет окно без контекста. Репозиторий публичный: github.com/stepachev/pia.

## Установка (одна команда)
```
git clone https://github.com/stepachev/pia.git ~/.pi-agent && ~/.pi-agent/install.sh
```
Вход в GitHub для установки не нужен (сохранять изменения в репозиторий может только владелец).
Установщик идемпотентный: ставит Command Line Tools (если нет — попросит дождаться и запустить снова), Node 22 LTS, зависимости, команды `pia` и `pia-login`, службы LaunchAgents из `launchd/*.plist.template`, сертификат подписи, собирает и ставит окно. Если уже установлено — только сообщит. `./install.sh --check` — показать, что будет сделано, ничего не меняя; `./install.sh --update` — обновить код и окно.

## Провайдеры и модели
pia работает с любым провайдером из библиотеки pi (`@earendil-works/pi-ai`): Anthropic (подписка Claude или API-ключ), OpenAI и ChatGPT Plus/Pro (Codex), Google Gemini, OpenRouter, GitHub Copilot, xAI (Grok), Groq, DeepSeek, Mistral, Cerebras, Fireworks, Hugging Face, Amazon Bedrock, Azure, Vertex и другие (полный список — `pia login` → «Другой провайдер»), а также локальные модели (Ollama, LM Studio, vLLM — любой OpenAI-совместимый адрес).

**Как подключить**
1. `pia login` — меню провайдеров (или сразу `pia login openai`, `pia login local`). Для подписки откроется браузер, для остальных спросит API-ключ (ввод скрыт).
2. Вход сохраняется в `~/.pi/agent/auth.json` (тот же файл, что у pi; права 600, вне git).
3. pia предложит переключиться на этого провайдера — ответ «да» запишет `~/.pi-agent/models.json`.
4. `pia --restart` — применить (обрывает работающих помощников). Проверить: `pia --models` (какие модели у ролей и есть ли доступ; запросов к моделям не делает).

**Роли:** `main` — главный (оркестратор); `smart` — помощник по умолчанию (`helper` с `model: smart`); `fast` — дешёвый помощник; `opus` — самая мощная модель провайдера (`model: opus`); `memory` — фоновый разбор памяти; `compact` — пересказ при сжатии разговора. Чего нет в файле — берётся из готового набора провайдера или у соседней роли (`smart`/`opus` ← `main`, `fast` ← `smart`, `memory`/`compact` ← `fast`).

**Конфиг** `~/.pi-agent/models.json` (вне git; другой путь — переменная `PIA_MODELS`). Нет файла — набор по умолчанию: Claude (Opus 5.5 главный и opus, Sonnet 5.5 smart, Haiku 5.5 fast/память). Роль — `"модель"`, `"провайдер/модель"` или `{ "provider", "model", "thinking" }` (`thinking`: off, minimal, low, medium, high, xhigh — подгоняется под возможности модели). Id моделей — из каталога pi-ai.

Примеры:
```json
{ "provider": "openai-codex" }
```
ChatGPT Plus/Pro (`pia login openai-codex`): готовый набор моделей, ничего больше писать не нужно. Так же с `"anthropic"`, `"openai"`, `"google"`, `"xai"`, `"groq"`, `"deepseek"`, `"mistral"`, `"github-copilot"`, `"openrouter"` — у них есть готовые наборы.
```json
{ "provider": "google", "roles": { "main": "gemini-pro-latest", "fast": "gemini-flash-lite-latest" } }
```
Gemini (`pia login google`, ключ с aistudio.google.com): свои модели для некоторых ролей, остальное — из набора.
```json
{ "provider": "openrouter", "roles": { "main": "anthropic/claude-opus-5.5", "smart": "deepseek/deepseek-v4-pro", "fast": "openai/gpt-oss-20b" } }
```
OpenRouter (`pia login openrouter`): модели разных авторов через один ключ. У id модели может быть «/» — провайдером считается только известное имя в начале.
```json
{ "provider": "ollama",
  "providers": { "ollama": { "name": "Ollama", "baseUrl": "http://localhost:11434/v1", "api": "openai-completions",
                 "models": [ { "id": "qwen3:14b", "input": ["text"], "reasoning": false, "contextWindow": 32768 } ] } },
  "roles": { "main": "qwen3:14b" } }
```
Локальная модель (проще: `pia login local` — спросит адрес, найдёт модели и запишет всё сам). Ключ не нужен для адресов `localhost`; для удалённого — `apiKey` в записи (строка, `"$ИМЯ_ПЕРЕМЕННОЙ"` или `"!команда"`, например `!security find-generic-password -ws имя`). Свои провайдеры `providers` — формат как у `models.json` в pi. Совет: маленьким локальным моделям тяжело работать с инструментами и браузером — их лучше брать для `fast`/`memory`.

Заметки: учёт трат `/usage` считает по стоимости из каталога pi (у локальных — 0); картинки оцениваются по правилам Claude, для других моделей — осторожнее (с запасом). Специальная подстройка кэша подсказок включается только для Claude (`anthropic-messages`). Если модель или провайдер указаны неверно, pia пишет причину в `errors.log` и работает на Claude.

## Вход к провайдеру
`pia login` (меню) или `pia login <провайдер>` — см. «Провайдеры и модели». `pia-login` (её ставит install.sh) открывает тот же выбор провайдера, что и `pia login`; `pia-login openai` — сразу провайдер openai. Потом `pia`.

## Окно
Окно: двойной правый Shift (с контекстом), двойной правый Option (показать/спрятать; встроенный, отключается `open pia://option-off`; не включать вместе с таким же хоткеем Raycast), Raycast «pia», Spotlight → pia или `open pia://show`; живёт в фоне (`~/Applications/pia.app`). Сертификат подписи («pia local signing») лежит в отдельной связке `mac-app/signing/`, её секрет — в Связке ключей macOS (служба `pia-signing`); подпись постоянная, поэтому разрешения не слетают при пересборке. Сборка вручную: `mac-app/build.sh` — обновляет только окно (сервер и рантайм `Contents/MacOS/pia` не трогаются, разговор и помощники не обрываются); `--full` — всё: бандл целиком и обе службы (также автоматически, если поменялся Node или plist сервера); `--no-install` — без установки. Голый `swift build` без build.sh падает на `@State` («SwiftUIMacros.StateMacro could not be found»): в Command Line Tools по умолчанию SDK 27, там `@State` — макрос, а плагина макросов SwiftUI в CLT нет; build.sh собирает с SDK 26.x из тех же CLT (`SDKROOT=…/MacOSX26.5.sdk`), Xcode не нужен.

## Имя процесса «pia» (а не «node»)
`mac-app/build.sh` кладёт в бандл копию Node под именем `pia` — `~/Applications/pia.app/Contents/MacOS/pia` (подписана тем же сертификатом и идентификатором `com.pi-agent.chat`, что и окно; hardened runtime у неё выключен — Node'у нужен JIT). Службы `com.pi-agent.server`/`memory` (plist с `AssociatedBundleIdentifiers` = `com.pi-agent.chat`), команды `pia`/`pia-login` и работяги (`process.execPath`) запускаются именно этим файлом. Поэтому Терминал при закрытии окна пишет «процесс pia», Мониторинг системы показывает pia, а запросы macOS (Запись экрана, Доступ к диску и т.п.) приходят от pia, а не от node. Имя берётся из имени файла (`ps -o ucomm`), поэтому `process.title` не трогаем (иначе ломается поиск `daemon.mjs` в `ps`).
- Обновление Node: рантайм — копия, сам не обновляется. После смены Node в `~/.local/share/pi-node` запусти `./install.sh --update` (или `mac-app/build.sh`) — копия обновится и подпишется заново; версия должна совпадать с той, под которую стоят `node_modules` (нативных модулей сейчас нет). `PIA_NODE=путь` — взять другой Node.
- Миграция со старой схемы: `./install.sh --update` пересоберёт окно с рантаймом, обновит обёртки и положит новый plist; применить: `launchctl bootout gui/$UID/com.pi-agent.server; launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.pi-agent.server.plist` (то же для `memory`). Разрешения, выданные раньше «node», нужно выдать заново для pia (мастер «Разрешения»); старые записи node в Системных настройках можно удалить вручную.
- Нет pia.app (окно не собралось) — обёртки и plist автоматически используют обычный Node.

## Разрешения macOS
При первом открытии окна pia показывает экран «Разрешения»: что нужно, зачем, есть ли сейчас (обновляется само). Включаются по одному кнопкой «Разрешить» (сначала системный запрос macOS, потом — нужный раздел Системных настроек); при запуске pia ничего не запрашивает. Без разрешений pia работает как обычный чат. Открыть экран снова: `/разрешения` в поле ввода, ⌘, в окне или `open pia://permissions`.
- **Универсальный доступ** (главное) — горячие клавиши (двойной правый Option и Shift) и чтение текста/выделения в активном окне.
- **Запись экрана** (необязательно) — снимок активного окна к сообщению. macOS применяет его после перезапуска окна — в мастере есть кнопка «Перезапустить pia» (служба не перезапускается).
- **Автоматизация браузеров** (необязательно) — адрес, заголовок и текст открытой вкладки; macOS спрашивает про каждый браузер отдельно.
«Мониторинг ввода» и другие доступы не нужны.

## Сохранение и удаление
- Сохранить код в GitHub: `./save.sh` (белый список в `.gitignore`, проверка на секреты). Память (`pia/память/`), история (`*.sqlite`), `auth.json`, `mac-app/signing/` в репозиторий не попадают — копируй отдельно.
- Удалить: `./uninstall.sh` (службы, окно, команды; `~/.pi-agent` и память не трогает).
- MCP (`mcp.json`): `notion`/`framer` — через `npx mcp-remote` (при первом запуске откроется браузер), `yab-browser` — нужен `/Applications/yab.app`, `figwright` — плюс плагин Figwright в Figma.

**Ленивые подключения (MCP).** В `mcp.json` у каждого сервера можно указать `"keepAlive": true` — он запускается со службой и работает всегда (так сделано для `yab-browser`). Остальные ленивые: при старте службы не запускаются, стартуют при первом вызове их инструмента и останавливаются вместе с деревом процессов (npx, обёртки, дочерние), если `"idleMinutes"` минут (по умолчанию 10) не было вызовов. Таймер считается от конца последнего вызова, сервер с вызовом в работе не останавливается. Одновременные вызовы во время запуска ждут один и тот же запуск. Список инструментов берётся из кэша `~/.pi-agent/pia/mcp-tools-cache.json` (вне git), он обновляется при каждом реальном запуске; если кэша нет (или поменялась команда/адрес сервера), при старте службы сервер один раз запускается, список снимается, и сервер останавливается. Вход (OAuth/токены) не затронут.

**Браузер Search (`search-mcp.mjs`).** Search (searchbrowser.app) спрашивает «… wants to use Search» при каждом новом соединении агента; «Always allow» он даёт только Claude Code — жёсткий список подписей в `Sources/Search/AgentTrust.swift` (`AgentLauncher.allowed`), его не расширить ни настройкой, ни `defaults`, ни подписью pia. Поэтому `search-mcp.mjs` (перенос `search-mcp` из репозитория Search на node, MIT) держит одно соединение: открывает его при первом вызове, в тишине раз в 4 минуты шлёт `status` (Search иначе отпускает через 5 минут) и сам прощается (`bye`) через `SEARCH_HOLD_MINUTES` (по умолчанию 60) минут без вызовов. Stop в Search рвёт соединение — пинги прекращаются, сам сервер не переподключается. В `mcp.json`: `"search": {"command": "~/Applications/pia.app/Contents/MacOS/pia", "args": ["~/.pi-agent/search-mcp.mjs"], "keepAlive": true}` (пути полностью). Итог: Allow — раз на сеанс работы с Search; снова — после часа без Search, после Stop или перезапуска службы.

## Правила для агентов, правящих pia
- **Тесты не писать и не запускать** (решение пользователя). Проверка — `node --check *.mjs`, `mac-app/build.sh --no-install`, `bash -n`.
- Перед правкой — копия рядом `*.before-<что>.*` (в git не попадают). Структуру файлов не менять — служба работает из этих путей.
- Службу без просьбы не перезапускать (`pia --restart` обрывает работающих помощников).
- Не открывать окна Терминала, не эмулировать клавиатуру, не трогать буфер обмена; не платить, не отправлять от имени пользователя, не удалять важное без разрешения.
- Секреты (вход, `server.json`, ключи и секреты подписи) в репозиторий не класть. Команды — с таймаутом, скрипты завершать.
- Журналы: `~/.pi-agent/*.log`, `mac-app/app.log`.



## Автозапуск и «Объекты входа» (SMAppService)
Службы `com.pi-agent.server` (сервер + память раз в 30 минут изнутри) и `com.pi-agent.chat` (окно, `--hidden`) лежат **внутри** `pia.app/Contents/Library/LaunchAgents` (plist генерирует `mac-app/build.sh` из `launchd/*.plist.template`) и регистрируются через `SMAppService` (`pia-app --register-only`; окно делает это и само при каждом запуске). В Системных настройках → Объекты входа это одна строка «pia» со значком приложения. Исполняемый файл окна — `Contents/MacOS/pia-app`, рантайм Node — `Contents/MacOS/pia`. `runtime-bin/node` — обёртка «node» → рантайм pia для MCP-серверов (PATH службы). Старые plist из `~/Library/LaunchAgents` build.sh переносит в `~/.pi-agent/backups/legacy-agents-*`. Состояние: `pia-app --autostart-status`.

## Остановка без модели

Сообщение целиком вида «стоп», «стой», «отмена», «хватит», «останови всё», `stop`, `/stop` (или с номером: «стоп 263», `/stop #263`) служба обрабатывает сама в `core.mjs` (`send` → `parseStop` из `shared.mjs`), не обращаясь к модели: останавливает помощников (та же функция, что у `helper_stop`) и текущий ответ, сразу отвечает «Остановил: #N.» и оставляет главному системную заметку. Работает в окне и в CLI, в том числе при исчерпанном лимите. Помощник, упёршийся в лимит (429, usage limit), не висит: повторы ограничены (`RETRY` в `guard.mjs`), затем он сдаёт отчёт «лимит исчерпан».
